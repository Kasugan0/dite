# V2 流水线契约设计

本文档定义 DITE 聚类重构 V2 的流水线契约。

它不写具体代码，而是先明确：

- 每一层做什么
- 每一层的输入输出是什么
- 哪些失败是正常语义，哪些是系统错误
- 哪些信息必须可观测

## 设计目标

V2 流水线必须满足这些要求：

1. 不再让一个阶段偷偷承担多种职责
2. 每一层都能独立解释自己的输入和输出
3. 每一层失败后，系统知道是继续、降级还是中止
4. 聚类结果必须能追溯形成路径

## 总体分层

V2 至少拆成 6 层：

1. 输入净化层
2. 文件特征层
3. 强连接召回层
4. 主题聚类层
5. 边界裁决层
6. 簇表示与报告层

## 1. 输入净化层

### 目标

- 识别并隔离最会污染后续聚类的输入问题

### 输入

- 原始文件列表
- 提取结果
- 提取遥测与缓存信息

### 输出

- 初步 `DocumentFeatures`
- `quality_flags`
- 提取质量摘要

### 必须完成的事

- 标记 `extraction_failed`
- 标记 `short_text`
- 标记 `filename_dominant`
- 决定某个文件是否进入正文语义主路径

### 明确不做的事

- 不做最终聚类
- 不做 LLM 裁决
- 不强行补全语义

### 失败语义

- 单文件提取失败是正常业务状态，不是全局错误
- 系统级崩溃、缓存损坏才是错误

## 2. 文件特征层

### 目标

- 从每个文件中构造多视图特征

### 输入

- 输入净化层输出

### 输出

- 完整 `DocumentFeatures`

### 必须完成的事

- 构造内容特征
- 构造文件名和路径特征
- 构造摘要、关键词、主题、领域等压缩语义
- 构造布局/模板提示

### 设计约束

- 文件名不再偷偷拼进正文 embedding
- 每类特征都要显式记录来源

## 3. 强连接召回层

### 目标

- 提前识别“几乎肯定存在关系”的文件对或局部团体

### 输入

- `DocumentFeatures`

### 输出

- `CandidateEdge`
- `CandidateComponent`

### 必须完成的事

- 找 near-duplicate 对
- 找高相似内容对
- 找文件名/标题/实体强一致对
- 形成初始强连接组件

### 明确不做的事

- 不直接给出最终主题簇
- 不靠这一层完成所有合并

### 契约要求

- 每条候选边必须有 `edge_type` 和 `evidence`
- 每个初始组件都必须能解释“为什么这些文件被提前绑在一起”

## 4. 主题聚类层

### 目标

- 在整理过的表示空间上抽取稳定主题结构

### 输入

- `DocumentFeatures`
- `CandidateComponent`

### 输出

- `ClusterDraft`
- 文件级临时标签

### 可以使用的机制

- 降维 + HDBSCAN
- 图社区发现
- 其他能在 V2 实验中站住脚的主题聚类器

### 契约要求

- 主题聚类层只负责形成结构草案
- 它不负责解释结果，也不负责解决全部模糊案例

### 失败语义

- 产出较多噪音点是允许的
- 过碎或过粗应被视为可诊断结果，而不是静默吞掉

## 5. 边界裁决层

### 目标

- 用更贵、更强、更保守的机制处理少量模糊关系

### 输入

- `ClusterDraft`
- `CandidateEdge`
- `DocumentFeatures`
- 约束信息

### 输出

- `AdjudicationRequest`
- `AdjudicationDecision`
- 修正后的成员关系

### 触发条件

- 小簇合并争议
- 文件归属不稳定
- 多个候选簇分数接近
- 高价值 `must_link` / `must_not_link` 冲突

### 可用机制

- 规则
- cross-encoder
- LLM

### 契约要求

- 任何进入这一层的案例都必须说明触发原因
- 任何离开这一层的结果都必须是结构化决策

## 6. 簇表示与报告层

### 目标

- 把最终结构变成可解释、可报告、可复核的结果

### 输入

- 修正后的簇成员关系
- `DocumentFeatures`
- `AdjudicationDecision`

### 输出

- `ClusterRepresentation`
- 最终用户 JSON
- 实验诊断信息

### 必须完成的事

- 为每个簇生成 `name / summary / keywords / topic / domain`
- 选择代表文件
- 生成形成证据摘要
- 暴露关键过程指标

## 缓存边界

V2 需要明确区分以下缓存层次：

1. 提取内容缓存
2. 文件级特征缓存
3. embedding 缓存
4. 裁决结果缓存

当前最不应该做的事是：

- 把所有中间结果都混进一个模糊缓存项里

## 可观测性要求

每一层至少要暴露：

- 输入计数
- 输出计数
- 跳过计数
- 降级路径计数
- 关键质量标记统计

V2 不允许继续只看最终簇数猜行为。

## 中止与降级原则

### 应继续运行的情况

- 单文件提取失败
- 单文件摘要失败
- 部分裁决请求超时

### 应降级运行的情况

- LLM 裁决不可用
- 某类元数据特征不可用
- 局部 embedding 生成失败

### 应中止的情况

- 文件扫描结果为空且不符合用户预期
- 特征层整体崩溃
- 聚类主路径没有任何可用输入

## 非目标

本文档不决定：

- 具体模型选型
- 具体配置项命名
- CLI 参数设计

这些属于更后面的实现与产品层问题。
